# FAQ

## Q1：为什么需要先"预览"？

预览是为了在执行前发现冲突并避免不可逆风险：
- 新名称重复
- 名称未变化
- 新名称为空
- 导出目标已存在（且未勾选覆盖）

冲突项在执行时会被跳过。

## Q2：复制和下载有什么区别？

- **复制**：从源文件夹选择文件，复制到目标子目录
- **下载**：从URL列表下载文件，保存到目标子目录

两者都支持序号自动命名和避免重复。

## Q3：为什么我选择了目录但看不到文件？

当前实现只读取"该目录下的文件"，并过滤掉子目录：

- `folder.listFiles().filter { it.isFile }`

如果资源在子目录，请在系统文件选择器中进入子目录后再选择。

## Q4：如何设置不同的目标子目录？

在"设置页"可以选择目标子目录，支持以下标准目录：
- `MP3`：MP3播放音频文件
- `DIYAUDIO`：音频贴自制DIY文件
- `REC`：系统录制的音频文件
- `DIYREC`：录音贴录制的音频文件
- `BOOK`：书本数据包
- `DICT`：英汉电子词卡文件
- `DIYREC2`：系统录制的音频文件

也可以输入自定义子目录名。

## Q5：序号是如何管理的？

- **按子目录分别维护**：不同子目录（MP3、DIYAUDIO、REC等）分别维护自己的序号
- **自动递增**：每次成功操作后，序号自动递增
- **避免重复**：默认开启，会扫描目标目录现有文件，确保新序号不会重复
- **手动调整**：可以在设置页手动修改当前序号
- **自动扫描**：可以点击"扫描目标目录并跳转到下一个可用序号"按钮

## Q6：为什么 Release 也用 debug 签名？

当前 `app/build.gradle.kts` 的 `release` 配置为了便于本地打包验证，临时使用了 debug signingConfig。

正式发布前建议：
- 配置独立 keystore
- 移除或替换 `signingConfig = signingConfigs.getByName("debug")`
